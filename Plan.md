# План тестирования и автоматизации приложения «В Хосписе» (FMHAndroid)

## 1. Общая информация

- **Приложение:** FMHAndroid («В Хосписе»)
- **Пакет:** `ru.edu.qamid`
- **Проект работает на:**  Android API 36
- **Архитектура:** MVVM + Repository + Hilt DI + Jetpack Navigation
- **Язык:** Kotlin
- **Бэкенд:** `https://students.netoservices.ru/qamid-diplom-backend/`
- **Локальная БД:** Room
- **Тестовые фреймворки:** Espresso 3.7.0, JUnit, Hilt Testing, MockWebServer

---

## 2. Границы приложения (Scope)

### Входит в область тестирования:

| Компонент | Функционал |
|-----------|-----------|
| SplashScreenFragment | Загрузочный экран, авто-проверка авторизации, переход через 3 сек |
| AuthFragment | Форма входа (логин/пароль), валидация, обработка ошибок |
| MainFragment | Отображение топ-3 новостей, меню, навигация |
| NewsListFragment | Полный список новостей, сортировка, фильтрация, раскрытие карточек |
| NewsControlPanelFragment | Панель управления новостями (CRUD) для администратора |
| CreateEditNewsFragment | Создание и редактирование новости, валидация формы |
| FilterNewsListFragment | Фильтр по категории, дате, статусу |
| OurMissionFragment | Отображение тематических цитат (8 статичных карточек) |
| Навигация | Все transition между фрагментами |
| Авторизация | JWT (access + refresh токены), автоматический refresh |
| Ролевая модель | Admin vs обычный пользователь |

### Не входит в область тестирования (Out of Scope):
- Серверная часть (backend)
- Нагрузочное тестирование
- Security-аудит (penetration testing)
- Кросс-платформенность (iOS, Web)

---

## 3. Типы тестирования

### 3.1 Функциональное тестирование
- Проверка всех пользовательских сценариев
- CRUD-операции с новостями
- Авторизация и аутентификация

### 3.2 UI-тестирование (Instrumented, Espresso)
- Отображение экранов и элементов
- Навигация между экранами
- Раскрытие/сворачивание карточек
- Empty states и error states
- Pull-to-refresh

### 3.3 Негативное тестирование
- Невалидные данные форм
- Отсутствие сети
- Ошибки сервера (401, 500, timeout)
- Попытка доступа без прав администратора

### 3.4 Интеграционное тестирование
- Взаимодействие Fragment → ViewModel → Repository
- Работа Room DAO запросов
- Token refresh механизм

### 3.5 Тестирование граничных значений
- Длина полей (пустые, минимальные, максимальные)
- Фильтрация по датам (до/после/граничные)
- Сортировка (ASC/DESC, пустой список)

## 5. Стратегия автоматизации

### Инструменты:
- **Espresso** — UI-тесты для всех экранов
- **Hilt Testing (`@HiltAndroidTest`)** — DI в тестах
- **MockWebServer (OkHttp)** — мокирование API-запросов
- **AndroidX Test Runner** — запуск на эмуляторе/устройстве

### Структура тестовых классов:
```
app/src/androidTest/java/ru/edu/qamid/
├── auth/
│   └── AuthTest.kt
├── navigation/
│   └── NavigationTest.kt
├── news/
│   ├── NewsListTest.kt
│   ├── NewsControlPanelTest.kt
│   ├── CreateEditNewsTest.kt
│   └── FilterNewsTest.kt
├── mission/
│   └── OurMissionTest.kt
├── splash/
│   └── SplashScreenTest.kt
├── main/
│   └── MainScreenTest.kt
└── util/
    └── TestHelper.kt
```

### Подход:
1. Использовать `MockWebServer` для имитации бэкенда
2. Hilt test компонент для внедрения mock-зависимостей
3. Idling Resources для ожидания асинхронных операций
4. Page Object паттерн для переиспользования элементов

## 6. План выполнения

### Этап 1: Подготовка
- Настройка тестового окружения
- Создание TestHelper/Page Objects
- Настройка MockWebServer + Hilt Test

### Этап 2: Базовая функциональность
- AuthTest — логин/логаут/ошибки
- NavigationTest — все переходы
- MainScreenTest — отображение главной

### Этап 3: Основная функциональность
- NewsListTest — список/сортировка/фильтрация
- NewsControlPanelTest — CRUD новостей
- CreateEditNewsTest — валидация форм

### Этап 4: Дополнительная функциональность
- OurMissionTest — экран миссии
- SplashScreenTest — загрузочный экран
- FilterNewsTest — фильтры

### Этап 5: Крайние случаи
- ErrorTest — сетевые ошибки
- EmptyStateTest — пустые списки
- RoleTest — разграничение прав

## 7. Критерии качества

- **Pass rate:** ≥ 90% тестов проходят
- **Покрытие:** все ключевые user flows
- **Стабильность:** тесты не flaky (повторяемы)
- **CI-ready:** тесты запускаются одной командой `./gradlew connectedAndroidTest`
