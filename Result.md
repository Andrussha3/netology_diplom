# Отчёт по автоматизированному тестированию

## Сравнение ручного и автоматизированного тестирования

| Критерий | Ручное тестирование | Автоматизированное тестирование |
|----------|-------------------|--------------------------------|
| Время выполнения одного прогона | ~6 часов | ~5-10 минут |
| Трудозатраты на регресс | Высокие (полный ручной прогон) | Низкие (запуск набора тестов) |
| Воспроизводимость | Зависит от исполнителя | 100% воспроизводимость |
| Выявление визуальных дефектов | Отлично | Ограничено (нужны скриншоты) |
| Тестирование ориентации экрана | Просто | Сложно (требуется эмулятор) |
| Тестирование масштаба шрифта | Просто | Сложно |
| Исследовательское тестирование | Да | Нет |
| Проверка accessibility | Просто | Сложно |
| Стоимость поддержки тестов | Низкая | Средняя/высокая |
| Быстрота обратной связи | Низкая | Высокая |

## Затраченное время

- Анализ проекта и документации: 2 часа
- Создание тестовой инфраструктуры (DI модули, Page Objects): 3 часа
- Написание UI-тестов: 5 часов
- Создание отчётной документации: 1 час
- **Итого: ~11 часов**

## Найденные проблемы

1. **Splash screen 3-секундная задержка**: Приложение показывает splash screen 3 секунды даже при наличии сохранённой сессии. Это замедляет автоматизированные тесты на 3+ секунды каждый.

2. **Отсутствие IdlingResource**: В приложении не используются механизмы синхронизации для тестов (Espresso IdlingResource). Тесты полагаются на автоматическое ожидание Espresso, что может приводить к нестабильности при медленных асинхронных операциях.

3. **Toast-сообщения**: Ошибки и уведомления выводятся через Toast, который не является view-элементом и сложно проверяется в автоматизированных тестах.

4. **PopupMenu для навигации**: Главное меню и меню авторизации реализованы через PopupMenu, что требует особого подхода при тестировании (поиск по тексту пункта меню).

5. **Невозможность установки даты раньше текущей**: Дата публикации новости не может быть установлена раньше текущей, что усложняет тестирование граничных значений.

## Рекомендации

1. Добавить Espresso IdlingResource для асинхронных операций.
2. Использовать Snackbar вместо Toast для сообщений об ошибках (лучше тестируется).
3. Уменьшить задержку splash screen или сделать её настраиваемой для debug-сборок.
4. Внедрить build-config поле для тестового base URL вместо замены модуля DI.
5. Добавить тестовые метки (testTag) для RecyclerView элементов.
